# 로드맵 — 미니 DBMS API 서버

루트 `src/` 엔진(Phase 1 SQL 처리기 + Phase 2 B+ 트리)을 그대로 두고, 그 위에 API 서버를 단계별로 얹는다.
매 단계가 끝나면 `make test` + `make e2e` 로 검증한 뒤 커밋한다. 다음 단계로 가기 전에 확인받는다.

```
[1] 베이스 서버 ──▶ [2] SQL API ──▶ [3] 스레드 풀 + 동시성 ──▶ [4] 마감
 소켓·HTTP·라우팅    JSON-RPC 2.0     worker pool, 작업 큐,       안전한 종료,
 GET /health        POST /rpc        락으로 데이터 보호           성능 비교, 문서
```

| 단계         | 상태  | 끝나면 되는 것                                             | 핵심 학습                                                           |
| ---------- | --- | ---------------------------------------------------- | --------------------------------------------------------------- |
| 1. 베이스 서버  | ✅   | `GET /health` 응답. 잘못된 요청에 400/404/405/408/413        | socket·bind·listen·accept, HTTP 파싱, recv/send 반복, 타임아웃, SIGPIPE |
| 2. SQL API | ✅   | `POST /rpc` 에 JSON-RPC 로 SQL 을 보내면 엔진이 실행하고 결과를 돌려준다 | 엔진–서버 경계, JSON 읽기·쓰기, JSON-RPC 오류 코드                            |
| 3. 스레드 풀   | ⏳   | worker N 개가 요청을 병렬 처리. 락으로 데이터가 깨지지 않게 보호            | mutex·condvar, 생산자–소비자 큐, rwlock, 동시성 테스트                       |
| 4. 마감      | ⏳   | Ctrl+C 에 처리 중 요청을 끝내고 종료. 스레드 수별 처리량 비교              | 시그널, join, 측정 방법                                                |

자세한 사용법·파일·함수 설명은 [README.md](README.md) 참고.
