# Phase 2. B+ 트리 인덱스

테이블마다 메모리에 B+ 트리 하나를 두고, 자동으로 발급한 `id`를 CSV 행의 시작 위치와 연결합니다. `SELECT ... WHERE id = 42`가 들어오면 트리에서 `42`의 위치를 찾고, `fseek`로 이동해 CSV 한 행을 읽습니다.

## 실행 흐름

| 작업 | 처리 방식 |
| --- | --- |
| 테이블 열기 | CSV를 한 번 읽으며 최대 ID와 각 행의 `(id, offset)`을 구합니다. 최대 ID에 1을 더해 다음 ID를 정하고, 각 쌍을 트리에 등록합니다. |
| `INSERT` | 다음 ID를 행 맨 앞에 붙입니다. CSV에 행을 추가한 뒤 반환된 바이트 위치를 그 ID와 함께 등록하고 다음 ID를 증가시킵니다. |
| `WHERE id = 정수` | 기존 컬럼·타입 검사를 거친 뒤 트리에서 ID를 찾습니다. 찾으면 해당 위치의 행을 읽고, 없으면 0행을 반환합니다. |
| 나머지 `SELECT` | 다른 컬럼 조건, ID 범위 조건, `AND`·`OR`·`NOT`으로 구성된 조건은 기존처럼 CSV 전체를 스캔합니다. |

인덱스는 메모리에 있으므로 DB를 닫을 때 해제하고 다음에 테이블을 열 때 CSV에서 재구축합니다. 메모리 할당이 실패하거나 기존 CSV에 중복 ID가 있으면 해당 테이블을 전체 스캔으로 조회합니다.

## B+ 트리 구성

- **리프 노드**는 정렬된 ID와 대응하는 CSV 바이트 위치를 저장합니다. CSV 첫 행의 위치 `0`도 유효하므로 검색 성공 여부는 위치 값과 따로 반환합니다.
- **내부 노드**는 구분 키와 자식 포인터를 저장합니다. 구분 키와 같은 ID는 해당 키의 오른쪽 자식으로 내려갑니다.
- **분할**은 새 키를 넣어 최대 키 수인 31개를 넘을 때 시작합니다. 리프는 새 오른쪽 리프의 첫 키를 부모에 복사합니다. 내부 노드는 중간 키를 부모로 옮깁니다. 분할이 루트까지 올라오면 새 루트를 만듭니다.

코드를 따라 읽을 때는 아래 순서로 보면 됩니다.

1. `run_insert`와 `run_select`에서 SQL 실행기가 인덱스를 호출하는 지점을 봅니다. [executor.c](../src/executor.c)
2. `bpt_find`와 `split_node`에서 검색과 분할을 봅니다. [bptree.c](../src/bptree.c)
3. `storage_append`와 `storage_read_at`에서 CSV 위치를 얻고 사용하는 방법을 봅니다. [storage.c](../src/storage.c)
4. `open_table`과 `db_close`에서 테이블을 열고 닫을 때 인덱스를 관리하는 방법을 봅니다. [db.c](../src/db.c)

## 테스트와 성능 비교

프로젝트 루트에서 실행합니다.

```sh
make test    # 분할, 검색, 재시작 후 조회 등 검증
make asan    # AddressSanitizer와 UndefinedBehaviorSanitizer로 테스트
make bench   # 100만 행 삽입 및 SELECT 시간 비교
```

`make bench`는 임시 테이블에 `user_1`부터 `user_1000000`까지 100만 행을 넣고 테이블을 다시 엽니다. 재구축이 끝난 뒤 같은 프로세스에서 아래 두 쿼리를 번갈아 각각 21회 실행합니다. 두 쿼리가 같은 ID 한 건을 반환하는지 확인하고, 결과 출력 없이 실행 시간의 중앙값을 비교합니다. [bench_index.c](../bench/bench_index.c)

```sql
SELECT id FROM users WHERE id = 750000;
SELECT id FROM users WHERE name = 'user_750000';
```

| 로컬 실행 예시 | 측정 시간 |
| --- | ---: |
| 100만 행 삽입 | 1.282초 |
| 테이블 열기 및 인덱스 재구축 | 0.072초 |
| ID 인덱스 조회 중앙값 | 13.00µs |
| 이름 전체 스캔 중앙값 | 48.40ms |

이 실행에서 ID 조회는 이름 전체 스캔보다 약 3,723배 빨랐습니다. 측정값은 실행 환경에 따라 달라집니다.
